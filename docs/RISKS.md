# Риски и ограничения

## Сеть и доступ

Prometheus, Alertmanager и Grafana на docker-сети без пароля. Защита снаружи — отсутствие публикации и nginx с TLS и basic auth на `127.0.0.1`. Контейнер, который попал в сеть `monitoring_internal`, читает метрики и алерты. Сокет Docker на хосте это и так root: кто может сделать `docker run --network monitoring_internal`, тот может больше, чем прочитать Prometheus.

`/healthz` прокси без пароля. Ответ — строка `ok`, без состояния бэкендов. При bind на localhost снаружи его нет.

Самоподписный сертификат на 90 дней. Браузер будет ругаться. Это не доверие УЦ. Алерт по TLS на сам прокси по умолчанию не настроен: цели — `example.invalid`. Когда сертификат прокси подойдёт к 14 дням, его не увидит blackbox, пока цель не добавят. Ротация — выпустить заново (`--force` у bootstrap ломает пароль Grafana, сертификат Ansible выпускает только если файла нет; для ротации файл удаляют вручную).

Пароль Grafana из окружения действует при первом старте базы. Повторная запись `compose.env` его не меняет. Сброс — процедура в runbook, не ansible-задача: пароль в аргументах `docker exec` попадает в список процессов.

`docker inspect` показывает переменные Grafana тому, кто имеет доступ к сокету. Файл `compose.env` на сервере — режим 0600, владелец root.

Basic auth nginx — один общий пользователь `monitoring`. Это не персональные учётки и не отзыв доступа по человеку. Хеш sha512-crypt (`$6$`), не секрет в git. Соль хранится рядом, чтобы повторный прогон не менял хеш. Заголовок `Authorization` прокси в бэкенды не уходит, у Grafana `auth.basic` выключен.

Смена пароля Grafana применяется `grafana cli admin reset-admin-password --password-from-stdin`, когда меняется файл пароля. Переменная окружения по-прежнему задаёт только первый старт базы. Пароль на короткое время есть в окружении процесса `docker exec`, не в argv.

## DOCKER-USER и docker-proxy

Правила смотрят исходный адрес назначения (`--ctorigdst` / `--ctorigdstport`) в `DOCKER-USER` и отдельно закрывают `INPUT`, где слушает `docker-proxy`. Исходящий трафик контейнера на чужой порт 8443 под них не попадает. `0.0.0.0` скрипт отвергает.

Пересборка идёт через `iptables-restore --noflush`, без окна, в котором фильтр снят. `ufw reload` может снять прыжок, которого нет в `after.rules`; следующий тик таймера (5 минут) или рестарт Docker (`PartOf=`) его возвращает. Если запись не удалась, метрика равна 0; если скрипт не запускался ни разу, ряда нет и это отдельный `absent()`.

На Docker 29 в этой ВМ цепочка `DOCKER-USER` была пустой, без хвостового `RETURN`. Вставка через `-I` всё равно нужна там, где Docker этот `RETURN` добавляет. Живой таймаут с адреса вне allow-CIDR здесь не воспроизводился: счётчик правила остался 0 из-за разъезда iptables-legacy и nft. Это ограничение проверки, не отказ от правила.

## node_exporter

В контейнер смонтирован корень хоста только на чтение, процесс без capabilities, uid 65534. Мирочитаемые файлы хоста, включая чужие конфиги с режимом 0644, процесс видит. `/etc/shadow` и пароль restic с режимом 0600 — нет, пока режим именно такой. Это не изоляция секретов. Компрометация экспортёра — чтение всего, что разрешено «остальным», и всех метрик.

overlay, tmpfs и fuse из алерта диска исключены: слой контейнера и служебные FUSE-монтирования шумят, а нулевой размер fuse даёт бесполезный ряд. Если `--path.rootfs` когда-нибудь уберут, на графике останутся только эти ФС, и алерт места пропадёт вместе с ними. На дашборде смотрите, что ряд — это `/` или `/var`, а не overlay.

## Textfile, restic, SSH

Парсер SSH хрупкий. Один источник за запуск. `journalctl _COMM=sshd` с пустым успехом не откатывается на `auth.log`: если на дистрибутиве бинарник называется иначе, счётчик будет нулём при `success=1`. Тогда задают `SSH_AUTH_LOG_FILE`. Из файла берутся последние 5000 строк. PAM-строка и строка sshd в одном файле могут удвоить попытку. Успешный вход с первого раза не виден. Часовые пояса классического syslog без года — локальные; тест фиксирует UTC через `SSH_AUTH_NOW_EPOCH`.

Метрики restic не содержат пароль и список файлов. Они говорят, что бэкап есть и какой он старый. Скрипт запускается от `restic-backup`, если такой пользователь есть (его создаёт роль backup в другом репозитории). Если пользователя нет, таймер не включается и через 30 минут горит `ResticMetricsAbsent`. Роль не делает парольный файл мирочитаемым и не вешает ACL.

Часы хоста — часть сигнала. Снапшот «из будущего» больше чем на 5 минут считается сломанным измерением. Малый перекос зажимается в ноль и выглядит как свежий бэкап. NTP эта роль не настраивает.

Окно SSH и пороги 20/100/15 не сняты с трафика. На хосте в интернете warning может стать фоном. Тогда порог поднимают по графику, а не выключают алерт.

## Приём алертов

Пустые receiver-ы — это тишина, не дежурство. Watchdog горит и тоже никуда не уходит, пока `vault_watchdog_webhook_url` пустой. Нельзя писать в отчёте, что «алерты настроены», если webhook не задан и кто-то не смотрит UI.

`example.invalid` не резолвится. Стенд, поднятый как в примере, будет гореть `HttpEndpointDown` и `TlsProbeFailed`. Так задумано: лучше красный пример, чем тихий запрос на чужой домен.

Inhibit в Alertmanager снимает warning, когда уже горит парный critical (диск, сертификат, SSH). Prometheus при этом держит оба ряда. Тесты правил это не прячут.

## Поставка и CI

CI не поднимает стек и не ходит в `example.invalid`. Он проверяет синтаксис, линтеры, `promtool test rules` и `docker compose config`. Живой UI, DOCKER-USER на FORWARD и чтение journald unit-ом на этом прогоне не доказаны, если в `docs/VERIFICATION.md` нет отдельной отметки.

Образы закреплены тегами. Это не pin по digest.

GitHub Actions: `permissions: contents: read`, action checkout закреплён полным SHA. `ubuntu-24.04` — всё ещё движущийся образ раннера.

Ansible `--syntax-check` не исполняет задачи. `--check` для этой роли почти пустой: генерация секретов и `compose up` пропускаются, потому что сухой прогон не умеет честно показать Docker. Это не доказательство идемпотентности.

## Чего не стоит делать, чтобы «починить» красный алерт

- `insecure_skip_verify: true` в blackbox.
- Публиковать 9100/9090/3000 «на время отладки».
- `chmod 777` на каталог textfile или на файл пароля restic.
- Удалять правила DOCKER-USER целиком (`iptables -F DOCKER-USER`): там могут быть чужие строки.
- `forget --prune` на хосте приложения. В репозитории backup это право только у admin-хоста.
- Глушить `ResticMetricsAbsent`, если бэкап на машине всё-таки есть: отсутствует сигнал, а не проблема порога.
